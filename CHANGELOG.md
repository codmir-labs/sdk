## Unreleased

### Features

* **feedback:** a visitor reads what became of their feedback and says whether the fix helped. `feedbackStatus(id, reporterToken?)` resolves `{ ok: true, state: 'received' | 'known' | 'fixed', release, fixedAt, reply, answer }` (the last four are `null` unless fixed) and `answerFeedback(id, better, reporterToken?)` sends `{ better }` and resolves the same. Both use the stored token on a page and only a given one on a server, never throw, never change the stored receipts (a `404` may be an older server), check every field of the answer, and send only the key, the token, the id and one boolean in headers and body: no cookie, no `keepalive`, no retry, no timer, no breadcrumb, span or `traceparent`, and never a token in a URL. New reasons: `not_found`, `not_fixed`; `refused` and `rate_limited` as for `sendFeedback`. Two `feedbackStatus` calls in flight for the same entry on a page are one request; answers go out in order, never merged. `/feedback` grows by 0.7 kB gzip. The answer limit rises to 8 KB. See `examples/feedback`.
* **feedback:** `@codmir/sdk/feedback` sends what an app's visitors say with the session it is about. `sendFeedback(text | { text, replyWhenFixed, replayId, eventId, failedRequest, pagePath, userId, storage, timeoutMs })` posts to the server's feedback door and adds, from the client `init()` made, the replay id, the id of the last error captured in the last 10 minutes, the newest failed request of the last 5 minutes to the page's own origin or a `tracePropagationTargets` match (never one of the SDK's own), the page path (never a query, fragment or origin), the environment, the release, `user.id` (never the email or name) and the SDK's version; what you pass wins and `false` switches one off. It never throws, resolves `{ ok, id, reporterToken, known }` or `{ ok: false, reason }` (`not_configured`, `empty`, `too_long`, `unauthorized`, `payment_required`, `rate_limited`, `refused`, `unavailable`), makes no breadcrumb, span, `traceparent` or cookie of its own, times out after 10 seconds and never retries; the same text in flight is one request. `deleteFeedback` and `listFeedback` use a receipt (id, token, time, never the text) kept in `localStorage` or memory. On a server, where one client serves every visitor, only what is passed is sent beside the environment and the release, nothing is kept and no calls are merged. No UI component. See `examples/feedback`.
* **express, nextjs, hono:** an error captured while a handler serves a request carries `request.url` (origin and path, never the query) and `request.method`. The request rides AsyncLocalStorage next to the tracing context, so concurrent requests never see each other's; an error outside any request has none. Express: `requestHandler`, `errorHandler`, `tracingHandler`; Next.js: `withCodmirTracing`, `withCodmirMiddleware`, `captureRequestError`, `captureRouterError`; Hono: `codmirTracing`. Headers, cookies and body are never put in `event.request`.
* **overseer:** `captureException` sends where the error happened: `contexts.browser`/`os`/`device` in a browser (from `navigator.userAgentData`, else a userAgent parse), `contexts.runtime`/`os` in Node, and in a browser `request.url` as origin and path only (never the query, hash, headers, cookies or body). In Node the first three in-app frames carry `pre_context`/`context_line`/`post_context` (5 lines each side, 240 characters per line, files over 1 MB skipped; turn off with `includeSourceContext: false`). Needs Node 20.16 or 22.3+ for ES modules (`process.getBuiltinModule`) to read the OS release and source files; CommonJS works on any supported Node.
* **logs:** `@codmir/sdk/logs` finds what is wrong in an app's own logs, on the app's machine with no account and no network. `createLogMonitor()` takes log lines (`record`) and served requests (`request`), keeps nothing raw (emails, IP addresses, tokens, JWTs, `token=` pairs, query strings and user agents are redacted before anything is stored, and `redact(redact(x))` equals `redact(x)`), groups them (a message with its numbers, ids, dates and quoted values folded, a JSON line or an object by its message; a request by method, path pattern and status; 500 groups at most), and every 15 minutes judges each group `new`, `alarm`, `back`, `known` or `noise`, with its last 96 batch counts. `@codmir/sdk/logs/node` adds `captureConsole`, `captureProcess` (uses `uncaughtExceptionMonitor`, so Node still prints the stack and exits with code 1), `fileSink` (JSON lines, mode 0600, rotated at 5 MB), and `expressLogs` and `honoLogs` middlewares. With `cloud: true` or `cloud: { apiKey }` each finding is sent as one issue through the SDK's own client, once an hour at most, at once when it is back, with the hits since its last send, capped at 50 per batch and 1,000 per day. Off by default. See `examples/log-findings`.

### Bug Fixes

* **overseer:** tags and breadcrumbs set inside a request stay in that request. On a server `setTag`, `setTags` and `addBreadcrumb` were process-wide, so one request's tenant tag, or its `instrumentFetch` or Express `http.request` breadcrumb, landed on another request's errors, messages and transactions. Inside a request they now write that request's own state, as `setUser` does; an event carries the process-wide tags and breadcrumbs with the request's on top (its tags win, and the newest 100 breadcrumbs are kept). Outside a request nothing changes.
* **overseer:** a BigInt or a circular value in an event no longer stops sending. It crashed a Node process and held back every later event in a browser. A BigInt is now written as its decimal string and a value that is its own ancestor as `"[Circular]"` (the same object reached twice side by side is written twice); an event that still cannot be serialized (a `toJSON` or getter that throws) is dropped and `onDropped` hears `unserializable`, and every automatic flush is a handled call.
* **overseer:** events are sent under steady load. The flush timer was pushed back by every capture, so a client that captured at least once a second sent nothing for as long as that lasted, and once 1,000 events were queued the oldest, errors included, were dropped. The timer now starts at the first unsent capture and is never pushed back, so events leave at most one second later, and a full batch (100 events or the byte budget of a request) is sent at once.
* **overseer:** repeats of one error are capped. A render loop or a failing poll sent every copy of one error, and every stored event is billed. The new `rateLimit` option (default `{ perGroupPerMinute: 10, perMinute: 100 }`, `false` turns it off) lets through at most that many `error` and `message` events per rolling minute for one group (the event's own `fingerprint`, else the default one) and in all, after `beforeSend`; transactions are never capped. The rest are not sent and `onDropped` hears them as `rate_limited` (`status` 0), in one call a second at most and on `close()`.
* **browser:** a click on an `<svg>` or `<path>` no longer throws inside the SDK's own listener, so the SDK stops capturing that `TypeError` as an error of the app. The click is a breadcrumb again (`svg.icon`), with `data.class` as the class string; the click and input listeners never throw into the page.
* **overseer:** `beforeSend` is guarded. A hook that throws drops the event and `onDropped` hears `before_send`, instead of the error escaping into the app; a hook that returns a Promise is awaited and `flush()` and `close()` wait for it, instead of the Promise being sent as `{}`; and the hook gets copies of `user`, the breadcrumbs and `contexts`, so it can no longer change the app's user or the next event's breadcrumbs.
* **overseer:** one group per error whatever id its message holds. The fingerprint masks UUIDs as `<UUID>`, then runs of 8 or more hex characters that hold a letter as `<ID>`, then digits as `<N>`. Digits used to go first, so every UUID or mixed hex id made a group of its own; a digit-only number masks to `<N>` whatever its length. Groups whose messages hold such ids start again once under the new fingerprint.
* **package:** under `require` every entry point shares one client, one tracing context, one replay hook and one request scope, as under `import`. The CommonJS build bundled each entry on its own, so after `require('@codmir/sdk/express').init(...)` the root `captureException` sent nothing and `/tracing`, `/replay`, `/logs` and `/feedback` saw no client. The build now splits the CommonJS entries into shared `.cjs` chunks (tsup `--splitting`). Every `exports` path, the names `require()` returns and the names `import` finds in a `.cjs` file are unchanged; the whole CommonJS dist is 90 KB gzipped instead of 223 KB. An app that loads the SDK through both `import` and `require` still has two clients, one per format. CI runs `src/__tests__/dist-one-client.test.ts`: each case in a new Node process against the built dist and a local server, under both formats.
* **verify:** `verify()` succeeds only when the server took its event. It used to report "Connection verified" with no DSN and no key (0 requests) and after a 401. It now sends one message with a client of its own and reads the answer: it fails, with one sentence in `error` and in the failing step that names the server and the status (never the key, a query or a body), when there is no `clientKey`, the answer is 401 or 403, 402, 404, 429, another 4xx or a 5xx, the host can not be reached, nothing answers within `timeout`, the answer is not the ingest address's, the answer says the event was dropped (an unknown key, no card and no balance are named in words: the server answers 200 to those), or the config drops it (`enabled: false`, `sampleRate: 0`, `beforeSend` returning `null`). It no longer calls `init`, so the app's client, its tags (`source=sdk-verify` and `sdk_version` went out with the app's later events), queue, breadcrumbs and replay are untouched, and it leaves no timer, listener or client behind. `printVerifyResult` prints `[FAIL]` and the sentence; `quickVerify(key, config?)` takes an optional config, and `quickVerify(dsn)` is `false` since a DSN has no key.
* **overseer:** `flush(timeout)` uses its argument: `true` when everything queued was sent or refused, `false` when the time ran out first (the sending goes on). Each caller has its own time, the timer is unref'd and cleared, and a late answer is no unhandled rejection. Without an argument it behaves as before.
* **express, hono, nextjs, remix, overseer:** each request has its own user. Express's `extractUser` called the process-wide `setUser`, so an event captured in one request's async tail could carry the user of another request that ran meanwhile (only `errorHandler`'s own capture was right), and the same held for any `setUser` an app called in a handler. The request scope now holds a user: inside a request an event's user is what `extractUser` answered (`null` or `undefined` means nobody, not the process-wide user) or what `setUser` was last called with in that request, and `setUser` inside a request leaves the process-wide user and the other requests alone. Outside a request `setUser` is process-wide as before; a request with no user of its own takes the process-wide one. Express calls `extractUser` once per request and again in `errorHandler` only when a later middleware has set `req.user`; an `extractUser` that throws no longer breaks the request (it threw out of the middleware before) and leaves the request without a user; `tracingHandler` shares the request's scope instead of opening a second one. Remix's `withCodmirTracing` and `withCodmirRequestHandler` now run the handler in a request scope too, so its errors carry `request.url` (origin and path) and `request.method`. The README lists which integrations keep the scope across `await` and where `setUser` is still process-wide (a handler that is not wrapped).
* **replay:** a picked radio button or checkbox is no longer recorded. rrweb stores `checked` in a snapshot and an added node and sends `isChecked` and the input's own `value` in an input event, whatever the input mask. With the default privacy (`maskAllInputs`), or with `radio` or `checkbox` in `maskInputTypes`, `checked` is taken off such a node (any case of the tag and the type, a node in an iframe or a shadow root too), a change of that attribute is dropped, and its input events and clicks are dropped whole. A `select`'s `selected` option is not recorded either. The node's `value`, `name` and label stay. The recorder keeps at most 50,000 ids to know the types and, beyond that, treats every input as hidden. With `maskAllInputs: false` and the type not named they record as before. The README lists what a recording holds and what it does not cover (custom `role="radio"` controls, `contenteditable`, the pointer's path).
* **replay:** CSS keeps no part of the page's query. rrweb resolves a relative `url(...)` against the page's address cut at its last slash, so `background: url(#bg)` on `/a/b?next=/x/y&token=abc/def` was recorded with `?next=/x/y&token=abc/` inside it, in a style attribute, a `<style>`, a stylesheet rule, an adopted stylesheet and a style declaration. The query is now cut there too, as it already was in links and sources; an absolute address of your own with a query of its own, and data URLs, stay.
* **browser, nextjs, express, remix, react-native:** `init` after `close` starts a new client. The entries set a flag in `init` and never reset it, so after `close` a later `init` was ignored: no client, no listeners, no config. Each entry's `close` now ends what its `init` started (the flag, the error and rejection handlers, the click and input breadcrumbs, the route breadcrumbs, the `console.error`, `fetch`, XHR and `history` patches, the pageload and navigation transactions, React Native's global error handler) and then closes the client, so a second `init` has one of each and its own config. `init` twice without `close` is still ignored. A patch another library, or a second copy of the SDK, put over one of ours is no longer taken off: it stays in place, passes every call on and records nothing, so two copies may close in either order. An error captured after `close` and before the next `init` is sent once, without retries, as before. The self-healing patch runtime no longer starts a timer or an observer when it was stopped while it loaded its manifest.
* **browser, nextjs, remix, react-native, tracing:** nothing throws where `window` exists and has no `location`, `history`, `document` or `addEventListener` (React Native sets `global.window = global` in 0.72 and defines `globalThis.window` in 0.88; a worker has no window). Without a location there is no navigation breadcrumb, no page context in an error and no pageload transaction; the pageload tracing, the route breadcrumbs, the self-healing patch runtime and the global handlers each check what they read. A `dsn` that is given is used as it is. The `/browser` case of `api-key-alias.test.ts` ran in the node environment, where `init` returns at once, and passed through a client an earlier case left; it now runs in jsdom.
* **logs:** a Vercel log drain's records are read as Vercel documents them. `statusCode: -1` is 500 (or the status the visitor got, `proxy.statusCode`), `proxy.statusCode: -1` is a revalidation and counts no request, a request counts once per `requestId` (with the worst status its records gave) however the records are fed, the path and method are the proxy's first, firewall and build records count nothing, and the platform's own lines (`START`, `END`, `REPORT`, `INIT_START`, an invocation's summary, its `report` and `metrics` records) are no text of the app. A record may give a request and a text. `RequestRecord` has an optional `replaces`, `parseLogLines` an optional third argument that carries the ids.
* **logs, overseer:** a finding the server did not take is sent again. With `cloud.apiKey` a finding that was refused (401, 402, a limit, a `droppedEvents` entry, or a queue that gave up) goes out again with its next hit, all its hits with it, a restart too, and its place in `perDay` is given back; after a refusal nothing is sent for 1 minute, doubled per refusal in a row up to 60 (`stats().cloud.pausedUntil`). The client's `onDropped` gets an optional `eventIds`, and is also called, with `status` 0, for events the client gave up on (a full queue, a closed client).
* **logs:** a release or a service keeps its name. The monitor took `web@1.4.0` for an email address, a commit for a hex secret, `dpl_…` for an id and a date stamp for a number, so every release of an app had one name and the platform could not tell the fix from the next release; `projects-production-checkout-worker-us-east-1` became `[secret]`. A name now stays when it is a commit, a version, `name@version`, `main-<commit>`, a date stamp, an epoch or plain words, and is dropped (no `release`, no `service`) when it holds an email address, an IP address, a JWT, a token, a `key=value` pair or a match of the app's own `redact` patterns. A saved state an older version wrote with `[hex]` in it loads, without those names. The prefixed secrets have their own form (`sk_`, `ghp_`, `npm_` + 20, `AKIA` + 16 and so on), so `skipped_records`, `skeleton-loader` and `npm-mirror-service` are no longer masked in log messages and no longer merge groups.
* **overseer, report, client:** the default addresses are on `https://www.codmir.com`. They were on the apex, which answers every request with a redirect: a browser refuses a redirect on the preflight `x-overseer-key` makes it send, so a page without its own `dsn` sent nothing, and `fetch` drops `Authorization` when a redirect leaves the host, so bug reports and the API client were never signed in. The default `dsn` is `https://www.codmir.com/api/v1/overseer`; a `dsn` you set is used as before.
* **package:** `sideEffects` is `false`. No module of the SDK does anything when it is imported, so a bundler may drop any chunk nothing uses. The old value marked every `dist/chunk-*` file as having side effects, which kept the API client's zod schemas, and zod, in an esbuild browser bundle of `import { init, captureException } from "@codmir/sdk"`: 80.8 kB minified, now 20.5 kB. CI now checks that every entry except `/express`, `/hono`, `/nextjs/server` and `/remix/server` bundles for the browser with esbuild and vite without reaching a Node built-in, and that a Next.js app importing `@codmir/sdk/nextjs` in a client component, `app/error.tsx`, `pages/_app.tsx` and an `instrumentation.ts` next to a middleware builds.
* **security:** breadcrumbs and the pageload transaction no longer carry a URL's query string or fragment. `fetch` and `XHR` breadcrumbs (message and `data.url`), the Next.js and Remix navigation breadcrumbs (`from`, `to`, the referrer and the `pushState`/`replaceState` target) and the pageload/navigation transaction's `data.url` keep origin and path only, so an `?access_token=` or an OAuth `#access_token=` no longer reaches Codmir with every error.
* **security:** an error report no longer carries the request's headers, cookies, authorization, query string, route params or body. Next.js `captureRequestError` sent every header; Express and Remix sent headers (minus a short list), the query and params; all of it went into `extra` and some into breadcrumbs. The integrations now send only the event's `request` (origin, path, method) and a `route` pattern. The core also cleans `extra` and breadcrumb `data` at `captureException`/`addBreadcrumb`: a `Request`/`Headers` value, a request-like object, and any key named like a request part or matching cookie, authorization, token, secret or password are dropped, so a future integration cannot bring the leak back. Express's `captureRequestBody` option is deprecated and ignored.
* **overseer:** stack traces parse V8 frames without a function, `async` and `new` frames, eval and native frames, and Firefox and Safari `fn@file:line:col` frames; `in_app` is false for `node_modules`, Node internals and the SDK's own files.
* **overseer:** a batch stays under the 256 KB the server takes. A request carries at most 240000 UTF-8 bytes as well as 100 events; an event too big on its own loses its oldest breadcrumbs, or is reported to `onDropped` as `too_large`; and a 413 halves the batch instead of dropping it. 100 events with many breadcrumbs used to go over the cap, and the 413 dropped all of them.

* **overseer:** errors now reach Codmir. Each error is sent as the `{type:"error", event, group}` wrapper the server stores, with a fingerprint computed like the platform's, instead of a flat event that was dropped behind a 200. Failed sends (non-2xx, network) are retried with capped exponential backoff and a bounded queue, `droppedEvents` is logged in debug mode, a browser flushes with `keepalive` on `pagehide`/hidden, and the default endpoint is always `https://codmir.com/api/overseer` rather than the page's own origin.
* **ci:** run `npm test` (the overseer suite) before the build.
